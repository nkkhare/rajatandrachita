# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static, single-page wedding save-the-date (Rajat & Rachita, Saturday May 15, 2027, Philadelphia), hosted at https://nkkhare.github.io/rajatandrachita/. There is no package manager, build step, framework, or test suite. **`dist/` is the hand-edited source, not build output.** Edit files there directly. The one exception is `dist/assets/art/*.svg`, which is generated by `art-src/` (see below).

## Commands

```sh
# Local preview (then open http://127.0.0.1:4173)
python3 -m http.server 4173 --bind 127.0.0.1 --directory dist

# The only checks CI runs; run them before pushing
test -s dist/index.html && node --check dist/invitation.js

# Regenerate the corner illustrations after editing art-src/ (deterministic, seeded)
node art-src/gen.mjs
```

## Deployment

`.github/workflows/pages.yml` deploys `dist/` to GitHub Pages on every push to `main` that touches `dist/**` or the workflow file. It can also be run manually with `workflow_dispatch`. A push to `main` is a public deploy.

The site is served under the `/rajatandrachita/` subpath. **All asset URLs must stay relative** (e.g. `assets/x.webp`, `styles.css`), with no leading `/`, or they break in production while still working in the local preview.

## Architecture

Three files work together, and none of them works fully alone:

- **Progressive enhancement is the core contract.** `index.html` ships with the envelope `#cover` marked `hidden` and the `#invitation` visible, so guests without JavaScript see the full invitation and calendar links. `invitation.js` calls `resetCover()` to switch to the envelope view only on its last lines, after every listener is attached. It returns early and leaves the invitation showing if the envelope image failed to load. Keep this ordering when adding behavior.
- **State machine:** `closed` → `opening` → `opened`, stored in `state` and mirrored to `.experience[data-state]`. CSS depends on `[data-state="opening"]`, which overlays the cover absolutely and clips overflow during the transition. Visibility is toggled with the `hidden` attribute (CSS forces `[hidden]{display:none!important}`) plus `inert`/`aria-hidden` on the invitation.
- **Opening animation** uses the Web Animations API through the `animate()` helper, which records every animation so `clearAnimations()` can cancel them. `animate()` ignores a missing element (returns `null`) so a markup change cannot throw into the `catch` and skip the whole sequence. `finishOpening()` is the single place where the page settles. It is reached from the skip button, Escape, window resize, a switch to reduced motion, an envelope image error, any animation exception, and the `finishTimer` fallback. `finishTimer` is computed from the animations' own end times (+50 ms), so timings can change freely.
- **The envelope is one photograph split into layers** inside `.envelope-art`: `.envelope-inside` (the interior wall), `.envelope-card` (a scaled replica of the invitation's blank card and corner art, sized with `cqw` units), `.envelope-pocket` (the `<picture>`), `.envelope-patch`, `.envelope-flap` (`.flap-front`/`.flap-back`, rotated in 3D about the hinge at 9.57% height), and `.seal-glow`. The layers only become visible in `[data-state="opening"]`; at rest the unclipped photo is all that shows. The `clip-path` polygons are in percentages of the 1536×1024 envelope image: the flap is the region above the flap's V plus the whole wax seal (center ≈ (768, 615), r ≈ 158 including its shadow), and the pocket is the region below the V. `.envelope-patch` fills the pocket where the seal sat with real envelope paper, magnified from the plain panel below the seal, plus a gold seam. If the envelope image changes, these polygons and the patch/flap-back background offsets must be re-measured.
- **The handoff:** the replica card rises out of the pocket, then the real `#invitation` (in front of the cover during opening, `z-index:5`, invisible until then) appears at the replica's exact position and scale and animates to its own layout position (a FLIP transform). This only happens when the invitation is landscape and the page height doesn't change; otherwise (phones, portrait tablets) the invitation fades in instead.
- **The banner and text drop:** the card arrives blank. Two lovebirds (`.bird`, inline SVG with a flapping `.bird-wing`) carry the rolled `#banner` down beak to beak, then back apart to unfurl it: `.banner-cloth` is revealed by a `clip-path` from the middle while `.banner-carrier-l`/`-r` (each 50% wide, holding a `.banner-roll` and a bird) translate outward in sync. Then the names, ornament, date, location and calendar drop in one by one. The CSS defaults are the final state (banner open, birds at the ends, rolls hidden), so no-JS, reduced motion and skip all land there. The right bird is the same SVG mirrored with the `scale` property, so the `transform` animations never undo the mirroring.
- **Reduced motion** is handled twice. JS skips straight to `finishOpening()`, and a CSS media query turns off all transitions and animations.
- **Focus management:** opening moves focus to `#skip-button`, and finishing moves it to `#invitation-title` (`tabindex="-1"`). `#replay-button` lives in the footer and is shown only once the invitation is open.
- **Invitation layout:** a 3-column grid (`28% | copy | 28%`) with the four `.corner-art` pieces in grid areas (`tl`/`tr` florals, `bl` Yosemite, `br` New York), so art can never overlap the centered text. On desktop the card keeps a 3:2 aspect ratio and its width is capped by the viewport height, `(100svh - var(--chrome)) * 1.5`, where `--chrome` is the vertical space of the masthead, padding and footer for each breakpoint tier. If you change those, update `--chrome` in that tier. The florals are tall (400×520): the cluster fills the top third and a vine cascades down the outer edge. On desktop, a `-40%` bottom margin on `.corner-tl`/`.corner-tr` lets that tail run beside the copy without growing the grid row. On phones (`max-width:760px`) and portrait tablets (761–1100px, portrait), the grid becomes `"tl tr" "copy copy" "bl br"` bands, and a larger negative margin pulls the copy up into the florals' open lower area.
- `styles.css` is written as dense one-line rules with design tokens in `:root` (`--paper`, `--card`, `--grain`, `--ink`, `--burgundy`, `--gold`, `--foil`, `--muted`, `--line`, `--serif`, `--sans`). Keep that style. Height tiers: `max-height:820px` and `max-height:650px` (both `min-width:761px`) tighten spacing for laptops and short windows; `min-width:1440px` handles wide screens.

## Corner art (`art-src/`)

`gen.mjs` composes the four SVGs from motifs in `motifs.mjs` (marigold, rose, lotus, jasmine, bud, mango leaf, jhumka, conifer, hatching, water) using the tiny geometry helpers in `lib.mjs`. Everything is emitted in absolute coordinates, so one `userSpaceOnUse` gradient reads as a continuous gold-foil sheen. Randomness is seeded, so output is reproducible. The palette is hard-coded to match the CSS tokens. `florals-right.svg` is a different arrangement drawn facing left and flipped inside the SVG, so don't mirror it again in CSS. Landscape outlines are left open along the artwork's own edges so no stroke reads as a frame line.

## Event details are duplicated

The date and location are hard-coded in several places, so a change must update all of them:
- `dist/index.html`: `<title>`, meta description, the `<time datetime>` and its spelled-out text, the location line, the footer, and the Google Calendar URL (`dates=20270515%2F20270516`, URL-encoded text/location/details)
- `dist/rajat-and-rachita.ics`: `DTSTART`/`DTEND` (all-day event, so `DTEND` is the exclusive next day), `LOCATION`, `SUMMARY`, `DESCRIPTION`
- `README.md`

## Constraints

- No external runtime dependencies: no CDNs, Google Fonts links, analytics, storage, or tracking. Fonts are self-hosted `.woff2` files in `dist/assets/` with their OFL license files. The page is `noindex, nofollow`.
- Raster images use `<picture>` with a WebP source and a PNG fallback. Update both files when replacing an image. The SVG corner art uses plain `<img>` (never `loading="lazy"`: the invitation starts hidden).
- `reference/wedding-crest.png` is the couple's supplied crest. It must not be modified, and it is intentionally outside `dist/`, so it isn't published or displayed. The envelope art was AI-generated; its prompt and provenance are recorded in `README.md`.
